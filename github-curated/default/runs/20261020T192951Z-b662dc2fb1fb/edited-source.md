REA, short for Reverse Engineer Anything, is an MIT-licensed TypeScript project; according to its README, it connects an agent to tools for inspecting native binaries, JavaScript and Electron applications, .NET assemblies, websites, Android APKs and devices, saved network and packet captures, firmware, model artifacts, and other targets [metadata][readme]. Its README describes an MCP-based workflow in which the agent inspects a local target, receives findings with evidence and limitations, and can use those results to explain behavior or write and test an implementation; the same workflows are usable from a command line [readme]. The maintainers position the project for lawful research, education, interoperability, software preservation, and analysis of software the user owns or is authorized to examine [readme].

According to the README, setup uses Node.js with npm and the command npx rea-agents setup; it registers REA's MCP server and matching workflow instructions, backs up existing configuration, and documents support for Claude Code, Codex, Cursor, Gemini CLI, and Grok Build, among others [readme]. The README states that REA requires Node.js 22.x at 22.19 or later, 24.x at 24.11 or later, or 26 or later [readme]. Target support adds dependencies: native binary analysis uses a caller-supplied Hopper, Ghidra, or IDA, though setup can optionally install Hopper with approval; static JavaScript and .NET inspection do not need a native analysis engine; Android APK analysis uses headless JADX and a full JDK; firmware work uses Binwalk or Unblob on Linux; some other analysis workflows require caller-supplied tools, including TShark for recorded packets and packet summaries, sigrok-cli for recorded logic signals, and pwntools for offline ELF layout and recorded Linux crashes [readme].

Documented caveats include local analysis with the agent receiving tool results while the model provider's data policy remains separate; Linux workflows for Ghidra, JADX, firmware tool launches, and static JavaScript or Electron analysis require a procps-compatible ps on PATH; and the 6.6.0 breaking changes state that older saved Evidence, analysis snapshots, and inventory observations are not migrated and must be regenerated [readme][release]. Release 6.6.0 also described Kuna as a caller-supplied static-analysis provider, with recorded real-provider coverage on Linux using Kuna 1.833 and no support for Windows, PE, or universal Mach-O; those release-specific limitations should not be assumed to define all current or future support [release]. Release 6.7.0 documents client-configuration fixes and says it includes the 6.6.0 changes [release].

REA-authored code is MIT-licensed, while third-party material keeps its own licenses and notices; the README states that commercial tools including IDA Pro and Hex-Rays decompilers, Hopper, and JEB must be legally obtained and used under their own terms, and that REA grants no license, key, or activation entitlement for them [metadata][readme].

HyperFrames is an open-source framework for turning HTML, CSS, media, and seekable animations into deterministic MP4 videos [readme]. The repository metadata identifies it as a TypeScript project under Apache-2.0 [metadata], and the README also states Apache 2.0 with no per-render fees or commercial-use thresholds [readme]. The README positions it for local use through a CLI, for AI coding agents via installable skills, and as a rendering core behind hosted authoring workflows [readme]. It says the skills teach agents to plan the video, write valid HTML, wire seekable animations, add media, lint, preview, and render [readme]. Documented use cases include product launch videos, PR walkthroughs, data visualizations, social videos, docs-to-video, PDF-to-video, and reusable motion graphics [readme]. Setup requires Node.js 22+ and FFmpeg; a basic CLI flow is npx hyperframes init my-video, then preview and render [readme]. Full-repository development uses Git LFS for golden regression-test baselines of about 240 MB of MP4 files, while source-only clones can skip LFS content [readme]. The README warns that standalone skills installed with skills add can lag main by hours and recommends npx hyperframes skills update when the newest copy or a non-interactive core install is needed [readme]. Studio is described as available but evolving [readme]. The release evidence records v0.8.181, published on 2026-10-20, with fixes and performance changes [release].

Agent Reach 是 Panniantong/Agent-Reach 的 Python 项目，采用 MIT 许可证；其目标是在单一 CLI 中为 AI Agent 提供读取和搜索互联网平台的能力。[metadata][readme]
README 将其定位为能力层：它负责接入方式的选型、安装、体检与路由，具体读取则由 Agent 直接调用上游工具完成。[readme][release] 它面向能运行命令行工具的 AI Agent 用户，例如 Claude Code、OpenClaw、Cursor、Windsurf；维护者还承接面向企业的 Agent 定制与落地合作。[readme]
支持场景包括网页阅读、YouTube 字幕与搜索、RSS、GitHub、Twitter/X、B站、Reddit、Facebook、Instagram、小红书、LinkedIn、Boss直聘、V2EX、雪球和小宇宙播客；不同平台所需的配置不同。[readme] 默认安装后可直接使用若干零配置渠道，需登录的渠道会由 Agent 询问后再配置。[readme]
安装入口是一句发给 Agent 的指令，更新同样通过一句指令完成；OpenClaw 用户需先开启 exec 权限，否则 Agent 无法执行 shell 命令。[readme][release] 项目宣称工具开源、API 免费，本地使用无需代理；若部署在服务器，代理可能约每月 1 美元。[readme]
凭据保存在本地的 ~/.agent-reach/config.yaml，文件权限为 600，不上传不外传。[readme] 对需要 Cookie 或登录态的平台，README 提醒存在平台检测与封号风险，建议使用专用小号。[readme]
项目采用首选加备选的多后端路由，doctor 命令会探测各渠道并报告当前使用哪个后端；一个渠道故障不会拖垮整个体检。[readme][release] OpenCLI 作为部分平台的桌面后端，需要桌面环境和 Chrome，npm 自动安装后还需在 Chrome 扩展商店手动点一次；服务器会自动跳过。[release]
Reddit 没有零配置路径，匿名接口已被封锁，官方 API 采用审批制，必须使用登录态。[readme][release] README 称选型基于真机实测并会定期复核。[readme][release]

Diagram Design is an Agent Skill from cathrynlavery/diagram-design that the maintainer describes as drawing editorial diagrams as one self-contained HTML plus SVG file, in the user's brand, with 45 diagram types and an opinionated style of one accent color, hairline borders, no shadows, and a four-pixel grid [readme]. Repository metadata describes editorial diagram design for Claude Code, Codex, GitHub Copilot, Cursor, Factory Droid, and Pi, with 44 diagram types, self-contained HTML plus SVG, no shadows, and “No Mermaid slop” [metadata]. The README also says each diagram type has one number, 01 to 44, while calling the set 45 diagram types; the metadata's 44 count and the README's 45 count conflict [readme][metadata].

Intended users work in Agent Skills-compatible hosts, including Cursor, Claude Code, Codex, Qoder, GitHub Copilot, Gemini CLI, Cline, Windsurf, and Amp [readme]. The skill accepts plain-language prompts for diagram types such as architecture, quadrant, and sequence with token refresh, and it can redraw draw.io, Mermaid, or Excalidraw sources with format, size, detail, and audience controls [readme]. Output is one HTML file with inline SVG that opens by double-clicking; motion is optional, defaults to none, and reduced-motion output shows a complete static frame [readme].

Setup can be done with npx skills add cathrynlavery/diagram-design for Agent Skills hosts, or with native plugin or install commands for Claude Code, Codex, GitHub Copilot, Factory Droid, Pi, and Qoder; the README also documents Claude Cowork, Kiro, OpenCode, and editable installs [readme]. The README states that official builds come only from this repository and that LittleMight, Cathryn Lavery's company, publishes the plugin directory listings [readme]. Brand onboarding fetches a website homepage, extracts a dominant palette and font stack, maps values to semantic roles, shows a proposed diff, and checks WCAG AA contrast before writing tokens [readme]. Named profiles stored under ~/.diagram-design/profiles/ can be selected per project with a .diagram-design marker [readme].

SVG and PNG export are documented; PNG export uses Playwright and requires one-time Chromium setup [readme]. By default a diagram loads Instrument Serif, Geist, and Geist Mono from Google Fonts, described as the only network request; system-font mode removes network requests [readme]. The license is MIT [metadata].

The maintainer notes real limitations: output quality depends on the model, the same prompt can lay out differently twice, and the result is not an editable source format with a text diff in a pull request or a canvas to drag [readme]. For documentation that lives in Git and changes every sprint, the README says Mermaid is still the better fit [readme].
